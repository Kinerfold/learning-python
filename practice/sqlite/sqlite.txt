 1. COUNT() - Посчитать

 Он посчитает строки, где price не является NULL. Значения NULL игнорируются.

 Можно использовать WHERE

 HAVING в GROUP BY
 HAVING фильтрует группы


 WHERE  → фильтрует отдельные строки
 HAVING → фильтрует группы



 SELECT company, COUNT(*)
 FROM products
 GROUP BY company
 HAVING COUNT(*) > 2

 Что делает: показывает только те компании, у которых больше 2 товаров.



 Можно использовать с WHERE, GROUP BY, HAVING

 SELECT company, COUNT(*)
 FROM products
 WHERE price > 30000
 GROUP BY company    Какие строки оставить? Выводит по company
 HAVING COUNT(*) >= 2


 1. WHERE → убираем товары с price <= 30000
 2. GROUP BY → группируем оставшиеся товары по company
 3. COUNT(*) → считаем товары каждой компании
 4. HAVING → оставляем компании, где товаров >= 2



 Отличия WHERE от HAVING в том, что WHERE фильтрует отдельные строки, а HAVING фильтрует группы.

 HAVING фильтрует группы ПОСЛЕ группировки

 Подзапросы в SQLite

 Подзапрос — это один SQL-запрос внутри другого SQL-запроса.


 SELECT *
 FROM products
 WHERE price > (SELECT AVG(price) FROM products)


 (SELECT AVG(price) FROM products) - Подзапрос находит среднюю цену

 Подзапрос становится таким:

 SELECT *
 FROM products
 WHERE price > 45000


 Подзапросы также может быть в SELECT


 Подзапрос = сначала получить какое-то значение/данные отдельным запросом, а потом использовать их в основном запросе.

 Сверху был Некоррелирующей подзапрос. Он просто находит среднюю цену и всё.



 Дальше будут Коррелирующие подзапросы


 SELECT name, age
 FROM users AS user
 WHERE age > (
     SELECT AVG(age)
     FROM users AS subuser
     WHERE subuser.company_id = user.company_id
 )

 Подзапрос смотрит на company_id текущего пользователя. 

 Поэтому такой подзапрос называется коррелирующим — его результат зависит от текущей строки основного запроса.

 Синтаксис EXISTS (подзапрос)

 EXISTS буквально говорит, "Существует ли хотя бы одна строка, подходящая под условие?"

 Если подзапрос нашёл хотя бы 1 строку - EXISTS возвращает 1. Если нет, то - 0


 Пример:

 SELECT EXISTS(
     SELECT id
     FROM users
     WHERE name = 'Alex'
 )



 В EXISTS обычно используется WHERE

 Пример: 

 SELECT *
 FROM companies
 WHERE EXISTS (
     SELECT *
     FROM users
     WHERE users.company_id = companies.id - «Для каждой компании проверь, есть ли пользователь, у которого company_id совпадает с id этой компании».
 );


 Запрос говорит - "Покажи компании, для которых существует хотя бы один пользователь."




 EXISTS - это проверка наличия хотя бы 1 строки. Ему будет всё равно, СКОЛЬКО нашлось. Главное, что есть хотя бы 1 строка


 NOT EXISTS - это противоположность EXISTS, то есть означает - "Не существует нм одной подходящей строки"


 Пример: 

 SELECT *
 FROM companies
 WHERE NOT EXISTS (
     SELECT *
     FROM users
     WHERE users.company_id = companies.id
 )



 IN и EXISTS очень похожи, но не всем.

 IN - "находиться ли это значение среди результатов?" - WHERE company_id IN (...)

 EXISTS - "существует ли хотя бы ОДНА подходящая строка?" - WHERE EXISTS (...)




 EXISTS проверяет: существует ли хотя бы одна подходящая строка.

 1. Есть заказ за 5000

 SELECT *
 FROM users
 WHERE EXISTS (
     SELECT *
     FROM orders
     WHERE orders.user_id = users.id
     AND orders.price = 5000
 );

 Смысл: у пользователя существует заказ с ценой 5000.

 ---

 2. Есть заказ дешевле 3000

 SELECT *
 FROM users
 WHERE EXISTS (
     SELECT *
     FROM orders
     WHERE orders.user_id = users.id
     AND orders.price < 3000
 );

 Смысл: существует хотя бы один заказ дешевле 3000.

 ---

 3. Нет заказов

 SELECT *
 FROM users
 WHERE NOT EXISTS (
     SELECT *
     FROM orders
     WHERE orders.user_id = users.id
 );

 Смысл: у пользователя нет ни одного заказа.

 ---

 4. Пользователь из Moscow + заказ > 6000

 SELECT *
 FROM users
 WHERE users.city = 'Moscow'
 AND EXISTS (
     SELECT *
     FROM orders
     WHERE orders.user_id = users.id
     AND orders.price > 6000
 );

 Смысл: пользователь из Moscow и у него есть заказ дороже 6000.

 ---

 5. Есть дешёвый заказ, но нет дорогого

 SELECT *
 FROM users
 WHERE EXISTS (
     SELECT *
     FROM orders
     WHERE orders.user_id = users.id
     AND orders.price < 3000
 )
 AND NOT EXISTS (
     SELECT *
     FROM orders
     WHERE orders.user_id = users.id
     AND orders.price > 10000
 );

 Смысл: есть заказ < 3000, но нет заказа > 10000.

 ---

 6. Цена от 4000 до 8000

 SELECT *
 FROM users
 WHERE EXISTS (
     SELECT *
     FROM orders
     WHERE orders.user_id = users.id
     AND orders.price BETWEEN 4000 AND 8000
 );

 Смысл: существует заказ в диапазоне 4000–8000.

 ---

 7. Товар содержит букву o

 SELECT *
 FROM users
 WHERE EXISTS (
     SELECT *
     FROM orders
     WHERE orders.user_id = users.id
     AND orders.product LIKE '%o%'
 );

 Смысл: существует заказ, название товара которого содержит o.

 8. Есть Keyboard И Mouse

 SELECT *
 FROM users
 WHERE EXISTS (
     SELECT *
     FROM orders
     WHERE orders.user_id = users.id
     AND orders.product = 'Keyboard'
 )
 AND EXISTS (
     SELECT *
     FROM orders
     WHERE orders.user_id = users.id
     AND orders.product = 'Mouse'
 );

 Смысл: существует Keyboard и отдельно существует Mouse.

 ---

 9. Заказ дороже средней цены ВСЕХ заказов

 SELECT *
 FROM users
 WHERE EXISTS (
     SELECT *
     FROM orders
     WHERE orders.user_id = users.id

 Смысл: есть заказ, цена которого выше общей средней цены.

 10. Заказ дороже средней цены этого пользователя

 INNER JOIN — памятка

 INNER JOIN — соединяет связанные строки из двух таблиц.

 Базовый синтаксис

 SELECT ...
 FROM table1
 JOIN table2
 ON table1.id = table2.foreign_key;

 * JOIN → какую таблицу присоединить
 * ON → по какому условию соединить таблицы
 * WHERE → какие строки отфильтровать
 * SELECT → какие столбцы показать

 Пример

 SELECT users.name, orders.product
 FROM users
 JOIN orders
 ON users.id = orders.user_id;

 Читается:

 > Соедини users и orders, где users.id совпадает с orders.user_id.

 users.id → ID пользователя

 orders.user_id → ID пользователя, которому принадлежит заказ

 Поэтому:

 ON users.id = orders.user_id

 связывает пользователя с его заказами.

 JOIN + WHERE

 SELECT users.name, orders.product, orders.price
 FROM users
 JOIN orders
 ON users.id = orders.user_id
 WHERE orders.price > 1000;

 Здесь:

 ON → как соединяем таблицы
 WHERE → что фильтруем

 Можно использовать несколько условий:

 WHERE city = 'Moscow' AND price > 1000;

 Алиасы

 Чтобы не писать длинные названия таблиц:

 SELECT u.name, o.product
 FROM users AS u
 JOIN orders AS o
 ON u.id = o.user_id;

 u → users
 o → orders

 Отличие от EXISTS

 EXISTS
 → «Есть ли подходящая строка?»

 INNER JOIN
 → «Покажи связанные строки из обеих таблиц»

 Формула

 FROM
  ↓
 JOIN → какую таблицу присоединить
  ↓
 ON → как соединить
  ↓
 WHERE → что отфильтровать
  ↓
 SELECT → что показать

 Главное для запоминания

 ON users.id = orders.user_id

 users.id — ID пользователя.

 orders.user_id — ID пользователя, которому принадлежит заказ.

 INNER JOIN показывает только те строки, для которых найдено соответствие в обеих таблицах.




 LEFT JOIN

 LEFT JOIN → показывает все строки левой таблицы + совпадения из правой.

 SELECT ...
 FROM users
 LEFT JOIN orders
 ON users.id = orders.user_id;

 Если совпадения справа нет → значения будут NULL.

 Найти пользователей без заказов:

 SELECT users.name
 FROM users
 LEFT JOIN orders
 ON users.id = orders.user_id
 WHERE orders.user_id IS NULL;

 Запомнить:

 LEFT JOIN → все слева
 IS NULL → нет совпадения справа
 ON → как связать таблицы

 UNION

 UNION → объединяет результаты нескольких SELECT в один результат.

 Базовый синтаксис:

 SELECT ...
 FROM table1

 UNION

 SELECT ...
 FROM table2;

 Пример:

 SELECT name, age
 FROM users

 UNION

 SELECT name, age
 FROM employees;

 UNION → убирает повторяющиеся строки.

 UNION ALL → оставляет повторяющиеся строки:

 SELECT name FROM users
 UNION ALL
 SELECT name FROM employees;

 Важно:

 * оба SELECT должны возвращать одинаковое количество столбцов;
 * типы данных должны быть совместимыми;
 * названия столбцов итогового результата берутся из первого SELECT.

 JOIN и UNION — не одно и то же:

 JOIN → соединяет связанные строки таблиц по условию ON.

 UNION → объединяет результаты SELECT друг под другом.

 Запомнить:

 JOIN → соединить
 UNION → объединить результаты

 EXCEPT

 EXCEPT → показывает строки, которые есть в первом SELECT, но отсутствуют во втором.

 SELECT name
 FROM users

 EXCEPT

 SELECT name
 FROM employees;

 Если:

 users:
 Mike, Alex, John

 employees:
 Alex, Bob

 Результат:

 Mike
 John

 Запомнить:

 UNION → A + B → объединить

 EXCEPT → A - B → исключить из A то, что есть в B

 Порядок важен:

 A EXCEPT B

 → строки из A, которых нет в B.

 Оба SELECT должны возвращать одинаковое количество столбцов.


 -----------------------------------------------------------------------
 -----------------------------------------------------------------------


 INTERSECT

 INTERSECT → оставляет только строки, которые есть в обоих SELECT.

 SELECT name
 FROM users

 INTERSECT

 SELECT name
 FROM employees;

 Например:

 users → Mike, Alex, John, Kate
 employees → Alex, Kate, Bob

 Результат:

 Alex, Kate

 Запомнить:

 UNION → A + B → всё из A и B

 EXCEPT → A - B → есть в A, но нет в B

 INTERSECT → A ∩ B → есть и в A, и в B

 Оба SELECT должны возвращать одинаковое количество столбцов.

 INTERSECT не соединяет таблицы как JOIN — он ищет общие строки двух результатов.
